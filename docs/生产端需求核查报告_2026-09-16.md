# 生产端需求与页面操作核查报告

核查日期：2026-09-16。范围：当前项目的生产侧；PI 对接仍等待用户生产验收，不作为本轮实现或验收目标。

## 1. 结论

**目前不能判定“所有生产侧需求已完成”，也不能判定“所有业务动作均可在页面闭环完成”。**

四码任意顺序扫描、任务恢复、整车绑定、聚合码、生产异常、厂内换件、入库等已经有实际后端实现及页面入口。当前主要缺口在追溯、打印补打闭环、岗位权限、查询导出和新旧页面一致性。

“数据真实”需要区分三个层面：

| 问题 | 本轮结论 |
| --- | --- |
| 页面是否连接后端、业务记录是否落库 | 是。抽查任务、扫描、车辆、打印队列、库存能够对应到数据库；不是纯静态演示页面 |
| 当前展示的是否是真实工厂生产数据 | 否。本轮连接独立验收库，车辆来自测试脚本、浏览器验收及开发初始化资料 |
| 所有展示值是否都由真实数据计算 | 否。较昨日涨跌、更新时间、通知数量等仍有固定值，旧组装进度也不是实际扫描进度 |

此前“测试通过”与“需求全部交付”不是同一结论。原实施清单中的完成标记应理解为相应实现/测试已开展；不能替代本报告发现的页面缺口和现场验收。

## 2. 核查方式与边界

- 以用户最新指示为准：电机、电池、车架、仪表无固定扫码顺序；先生产，验收后再 PI。
- 对照 [项目建设方案](生产与PI订单系统_项目建设方案.md) 的生产相关编号，检查 Vue 页面、Controller、Service、Mapper 和当前数据库。
- 使用 Playwright 实际登录 Web/H5，检查页面入口、任务恢复、追溯、打印队列、生产库存、组装进度、零部件和入库记录。
- 本轮未提交扫码、入库、换件、补打、解除隔离等业务写操作；未修改业务源码、公共接口或业务表结构。登录及服务启动属于验收环境操作。
- 本轮运行已有构建产物，没有重新构建或重跑上一轮 110 项测试；历史测试不作为本轮新取得的证据。
- 原 18080 端口被其他程序占用，未终止该程序。另启动本机 API 18180、Web 5183、H5 5184；临时前端代理配置在 `output/production-audit/`，未修改项目默认配置。
- 验收库为 `127.0.0.1:13316/bike_production_acceptance_20260916`，MariaDB 11.4，Flyway 版本 16。未审计企业正式库或实际工厂数据。
- 未连接现场 PDA 扫码枪、标签机、腾讯云 COS 或云 MySQL；实物出纸、正式云环境和现场连续作业不能标记通过。

## 4. 已确认的问题

### P1-01：Web 追溯主入口错误，H5 没有展示完整链路

**实际复现：**Web → 全链路追溯 → 开始追溯查询，弹出“新增全链路追溯”，字段为编码、名称、联系人、联系电话，不是总码/车架/部件查询。

原因：`openPrimaryAction()` 没有处理 `trace`，落入通用资料创建分支。追溯列表本身来自操作日志，搜索只过滤这些列表列值，不能代替按总码和任意历史部件查车。列表详情中车架为 `-` 时还会请求无效车架。

H5 输入 `EDGEB60DC0-FRAME` 并点击“查询完整链路”，页面只显示“组装完成 · 长续航款 · 绑定历史 3 条”。同一 API 实际返回车辆、绑定历史、生产事件、入库、出库和换件记录，页面没有渲染这些明细。Web 对已关联车架的详情主要以英文键和 JSON 字符串展示对象，也未形成面向用户的完整追溯视图。

- 代码：[Web 操作分发](../bike-web/src/App.vue#L638)、[H5 追溯结果](../bike-h5/src/App.vue#L273)、[追溯列表 SQL](../bike-server/src/main/resources/mapper/ModuleMapper.xml#L109)。
- 页面证据：[错误表单截图](../output/playwright/audit-trace-wrong-dialog.png)、[H5 摘要截图](../output/playwright/audit-h5-trace-summary.png)。
- 验收要求：三个编码入口均可用，包含历史旧件，页面展示实际明细及时间、人员、原因；空关联记录不能错误请求 `-`。

### P1-02：补打有建任务入口，但缺少完整页面执行路径

Web 打印队列提供预览、填写原因创建补打任务。实际送印依赖 Windows 打印客户端。H5 人工打印、回报结果和标签预览均写死为 `FIRST-${task.id}`，不能选择补打产生的新任务 ID。

因此，自动打印客户端未运行时，用户能从 Web 创建补打，却不能通过现有页面选中该补打任务完成“人工打印 → 回报结果”。H5 也未展示该车打印任务的实时状态。不能把“已生成打印任务”描述为“标签已打印”。

客户端需要命令行配置 token、打印机等并启动；没有终端配置、在线状态、登录续期的管理页面。客户端的领取和结果回报异常在业务打印捕获范围之外，连接/鉴权失败后缺少持续恢复机制。物理打印依赖本地程序本身合理，但当前异常恢复和人工补打入口未闭环。

- 代码：[H5 首打固定路径](../bike-h5/src/components/ProductionStation.vue#L23)、[Web 补打创建](../bike-web/src/components/ProductionManager.vue#L248)、[打印客户端](../tools/print-client/client.mjs#L9)。
- 验收要求：页面可以按车辆查看全部打印任务及真实状态，对允许重试的任务完成授权人工打印/回报；终端离线、过期、失败、结果未知均有可执行的处理办法。

### P1-03：新旧生产与库存入口口径不一致

旧“组装进度”查询车辆表，进度只显示 `0 / 4` 或 `4 / 4`，当前工位固定为“总装工位”。未读取新任务和扫描表。真实存在的 1/4 作业任务在新生产中心/H5 可见，在旧页无法准确体现；车架尚未扫描时尤其明显。

当前库存总览包含 4 台，生产中心 SKU 库存仅包含 2 台。后者页面确实注明“显示通过生产任务建立的整车”，因此不是凭空造数，而是两套统计范围并存。旧库存与总览的可用数量仅扣锁定，未扣生产隔离；当前样本没有入库中隔离车辆，该差异属于已确认的计算逻辑缺口，未在本轮新增隔离数据复现。

旧 `AssemblyServiceImpl.submit()` 仍能走既有整车四码组装，未强制建立生产 SKU 扩展和首打任务。它保留占用/隔离保护，但与新生产流程的产物不一致，需要明确旧入口的兼容或停用策略。

- 代码：[旧组装/库存 SQL](../bike-server/src/main/resources/mapper/ModuleMapper.xml#L6)、[新库存 SQL](../bike-server/src/main/resources/mapper/ProductionMapper.xml#L5)、[旧组装入口](../bike-server/src/main/java/com/bike/server/assembly/AssemblyServiceImpl.java#L65)。
- 验收要求：生产进度以任务和实际扫描为准；明确统一的库存范围和隔离扣减口径；旧 API 不再产生缺少 SKU/首打的新增生产记录，或提供清晰兼容策略。销售订单占用仍留 PI 阶段，不计为本轮必须实现项。

### P1-04：查询和导出未达到需求清单

- 新生产任务仅有任务/编码/批次关键词，缺少 SKU、日期、状态等组合筛选。
- 生产库存可选 SKU、仓库，能显示库位，但不能按库位筛选。
- 库存、入库、出库导出接口存在，Web 对应页面没有导出按钮；工具栏分别用于锁库、办理出入库。整车和操作日志有导出入口，不能笼统称为全部导出都没有实现。
- 整车列表、详情 DTO 和对应导出尚未合并生产 SKU、批次资料；按 SKU 查询整车档案不能通过当前列表闭环。
- 通用导出没有携带页面搜索条件，导出范围与筛选后列表不一致。后端已实现分页读取全部记录，本轮没有发现“只导出首 100 条”的问题。

代码：[页面导出](../bike-web/src/App.vue#L596)、[按钮分发](../bike-web/src/App.vue#L638)、[生产查询](../bike-web/src/components/ProductionManager.vue#L121)、[导出 Controller](../bike-server/src/main/java/com/bike/server/transfer/ExcelTransferController.java#L19)、[整车列表字段](../bike-server/src/main/resources/mapper/ModuleMapper.xml#L13)。

验收要求：生产相关列表能够按约定字段查询，库存及出入库从页面导出，导出字段、条件和实际记录一致。

### P2-01：存在没有数据计算依据的展示值

首页六项指标“较昨日”均固定 `+0%`；“数据更新时间：刚刚”、通知数字 `3` 固定；通知按钮无操作。最近操作的状态固定为“已完成”，并非对应任务当前状态。

数量、七日趋势和列表主要来自数据库，不能因此判为全是假数据；但上述固定值会误导用户，需真实计算或去掉相关展示。

代码：[统计 Service](../bike-server/src/main/java/com/bike/server/dashboard/DashboardServiceImpl.java#L22)、[最近操作 SQL](../bike-server/src/main/resources/mapper/DashboardMapper.xml#L25)、[首页展示](../bike-web/src/App.vue#L859)。

### P2-02：部件导入缺少模板和失败明细页面

SKU 导入已经有模板下载、成功/失败统计、失败原因展示。零部件页面只有“导入 Excel”，未提供同等模板下载入口；后端返回 `failures`，页面仅提示成功/失败条数，未展示错误行和具体原因。

代码：[通用导入页面逻辑](../bike-web/src/App.vue#L615)、[后端导入结果](../bike-server/src/main/java/com/bike/server/transfer/ImportResult.java#L5)、[SKU 导入对照](../bike-web/src/components/ProductionManager.vue#L386)。

验收要求：普通用户从页面取得部件模板，按错误行修改并重新导入，无需查看接口响应。

### P2-03：按岗位授权后，部分按钮仍不可达

`canWriteActiveModule` 对非超级管理员仅匹配零件、订单、锁库、意向等有限模块，没有出入库模块映射。结果是后端允许持有 `STOCK_IN_OPERATE` / `STOCK_OUT_OPERATE` 的人员更正出入库，但 Web 的撤销按钮仍只对超级管理员满足显示条件。

角色可多选，但用户工位关联仍是单个 `workstationId`，不能配置“只允许电机+电池”这样的工位组合；选择 ASSEMBLY 会放开全部四码。SKU、模板、解除隔离、旧件复检管理又固定要求 SUPER_ADMIN。是否全部由超级管理员负责需要作为交付口径明确，不能等同于任意生产主管岗位已可配置。

本项为前后端源码核对，本轮未新建普通岗位账号逐一试操作。

代码：[页面权限判断](../bike-web/src/App.vue#L206)、[后端撤销权限](../bike-server/src/main/java/com/bike/server/stock/StockServiceImpl.java#L117)、[用户单工位 DTO](../bike-server/src/main/java/com/bike/server/system/UserCreateRequest.java#L6)、[工位关联查询](../bike-server/src/main/resources/mapper/UserMapper.xml#L20)、[生产管理权限](../bike-server/src/main/java/com/bike/server/production/ProductionAccess.java#L57)。

### P2-04：图片和标签仍有交付缺口

- 产品/异常图片有上传、鉴权读取和预览实现，但图片弹窗没有明确下载动作；依赖浏览器右键保存不等同于完整的移动端下载功能。
- 产品图片入口位于 SKU 编辑弹窗，只有管理权限才显示编辑操作，只读人员缺少独立查看商品图片入口。
- 两种标签布局已能生成，当前主要差别是二维码尺寸；最终客户样稿、字段排版、实际纸张尺寸和现场型号尚未验证，不能认定两套客户版式已交付。
- 本地图片存储有上一轮验证记录，实际 COS 接入仍待云账号联调。

代码：[图片预览](../bike-web/src/components/ProductionManager.vue#L284)、[商品图片入口](../bike-web/src/components/ProductionManager.vue#L593)、[标签生成](../bike-server/src/main/java/com/bike/server/production/ProductionLabelService.java#L26)。

### P2-05：部分日志和业务边界需要明确

成功的生产操作有日志并能通过追溯 API关联。本轮抽查 `EDGEB60DC0-FRAME`，API 返回创建任务、四次扫描、绑定、首打、打印领取、补打、异常等 13 个事件。

但非法扫码在业务校验抛错前没有独立落库记录，旧页面所称“异常扫码记录”尚不能直接核对失败次数和原因。当前换下的旧件一律进入 `QUARANTINED / FAILED`，复检通过后才允许复用；这是比“仅不良件禁用”更严格的实现，应在验收说明中写明，避免用户误认为普通换件旧件可直接重装。

代码：[扫码校验与成功日志](../bike-server/src/main/java/com/bike/server/production/ProductionServiceImpl.java#L147)、[旧件隔离 SQL](../bike-server/src/main/resources/mapper/ReworkMapper.xml#L10)。
