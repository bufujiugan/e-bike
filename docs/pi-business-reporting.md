# PI业务看板与列表导出

对应生产与PI PRD 6.7.3、6.10。看板在PI工作区展示，需内部Web账号及PI_READ；功能权限与内部客户授权范围同时生效。计数与明细使用同一SQL条件，先过滤再分页，单页最多100条；不会读取前100条再当成全量统计。

| 队列 | 统计对象与边界 | 附加权限 |
| --- | --- | --- |
| EXPIRING_LOCKS | 未来24小时内到期、仍有未转换未释放数量的有效临时锁定；不含已到期、全部转换或释放 | AGENT_LOCK_WRITE或AGENT_INVENTORY_READ |
| MISSING_PI | 待完善的PI草稿（含修订草稿）；有ORDER_READ时同时包含尚无PI关联的有效订单 | 查看订单部分需ORDER_READ |
| AWAITING_PAYMENT | 当前已发布版本，系列累计有效到账小于该版总金额；撤回登记不计入有效到账 | 与PI财务详情一致的财务权限 |
| AWAITING_SHIPMENT | 当前已发布版本，有未发数量且尚未发货；包括未放行或未建立履约订单的单据 | 无 |
| PARTIAL_SHIPMENT | 当前已发布版本，已发部分且仍有未发数量；关闭/取消子单的余量不计入 | 无 |

已发布队列按系列当前版计一次，历史版不重复累计。不同队列允许交叉，例如未收足款的单据也可能待发货。无财务权限时收款队列返回null，明细不返回paidAmount；无锁定权限时到期锁定返回null。代理不能访问内部看板。无客户的历史锁定仅显式全范围岗位可见。

## 查询与导出

- `GET /api/pis/dashboard?keyword=`：五类计数，关键词为业务编号或客户名称。
- `GET /api/pis/dashboard/{queue}?keyword=&page=1&pageSize=20`：SQL分页明细和同条件total。
- `GET /api/pis?keyword=&status=&page=&pageSize=`：PI号、客户名/编号、SKU编号、履约订单号、出库单号、真实出库批次号、物流批次号或运单号。关联检索覆盖系列历史，最终仍按PI客户/代理权限过滤。
- `GET /api/pis/export.xlsx?keyword=&status=`：需PI_READ与PI_EXPORT，导出筛选结果全部分页，并沿用列表客户范围。代理仅导出自己的已发布PI，不含收款字段。

导出包含编号、版本、客户、内外销、币种、总金额、状态、负责人、创建/计划发货时间，以及已发、未发、关闭数量。无履约订单时未发/关闭数量留空；有财务权限另含付款状态与已确认到账。编号和文字写为字符串，避免前导零丢失与公式注入。金额保留两位格式；超出Excel安全精度时用文本保存完整分位并附批注。看板API金额也采用十进制字符串。导出不包含银行账号或收款凭证。

导出在一致性读事务内按100条分批读取，范围锁与撤权互斥；成功需保存PI_LIST_EXPORT审计。记录数超过Excel容量显式要求缩小范围，不静默截断。响应禁止缓存；任务与文件归档下载是另一组接口，不受列表导出替代。

## 检查

`PiReportMysqlTest`使用真实MySQL和生产mapper，覆盖五队列、修订/历史收款、实际出库与关闭余量、105条完整XLSX内容、权限/撤权/审计失败及跨字段搜索。`tools/acceptance/pi-conversion-api.mjs`覆盖普通账号HTTP路径。详细执行结果记录在实施台账；这些属于实施回归，不计最终两轮全项目需求验收。
