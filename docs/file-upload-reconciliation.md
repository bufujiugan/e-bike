# 上传绑定失败核对（V49）

生产异常/SKU图片、PI确认/收款/物流附件、售后附件、PI导出归档共用持久化上传记录。对象写入前先通过独立的两连接池提交上传意图，再由业务事务锁住该记录，直到业务附件或归档引用提交。意图表不引用用户、订单等父表，避免外层事务已持有父行锁时独立提交互相等待。部署数据库连接预算须另计这两个连接。

成功绑定在同一事务把记录标为BOUND。上传、元数据、审计或归档绑定失败时，业务事务回滚，独立记录进入REVIEW；即使回滚清理已成功，记录仍保留。提交结果不明时不按回滚删除对象；重启后由记录和业务引用重新核对。新写入文件验证实际内容后才绑定；归档及售后也执行存储后字节/摘要检查。

PI归档同样只在事务明确回滚时执行即时对象清理。提交结果不明时，即使一次普通读取暂未查到归档引用，也不据此删除；保留对象交由持久记录和业务引用核对。

## 状态及恢复

- PENDING：尚未提交绑定，可能仍在上传。创建超过15分钟的记录每分钟扫描一次，每次最多20条；行锁被业务持有时SKIP LOCKED跳过，不以超时为由删除进行中的文件。
- BOUND：已有业务引用。普通核对可检查存储是否可访问，但本入口禁止清理；缺失文件提示存储恢复问题。
- REVIEW：待人工核对。文件存在/已不存在/无法检查单独记录，不能把已删除的文件显示成仍有残留。核对不会重新绑定，也不提供文件内容下载。
- CLEANUP_PENDING：授权人员已明确申请清理，操作原因、版本、人员及历史已提交。再次确认没有任一业务引用后才删除；删除或状态保存失败可重试，重启后每分钟处理已等待一分钟的申请。
- CLEANED：已确认文件不存在，保留上传与核对历史；不删除历史记录。

引用检查覆盖生产附件、PI确认/付款/物流附件、售后附件、PI归档PDF/XLSX及旧付款凭证字段，并添加索引。新写入对象键仅由后端生成，没有客户端绑定任意对象键的接口。清理与上传以同一记录行锁串行；核对使用READ_COMMITTED非锁定读取业务引用，避免反向获取业务父锁。

## 权限与审计

Web“系统管理 → 上传失败核对”需要内部FILE_REVIEW_MANAGE；迁移不自动分配给任何普通角色。该权限允许全业务失败上传元数据运维核对，应只明确分配给受信运维岗位，不等于客户业务资料或附件内容下载权限。代理/PDA即使意外同时有管理员角色也不能进入。

人工核对及清理申请均须最新version、1至500字原因，写入专门的核对历史并保留最新原因；通用日志只记录状态/版本，不泄露文件名、客户业务标识、存储键或自由文本原因。任一审计失败回滚核对/清理申请，文件不会被删除。并发版本变化返回FILE_REVIEW_CONFLICT，进行中的上传返回FILE_REVIEW_BUSY。

V49之前仅日志记录的历史残留对象不会被伪造为已登记上传；此版本覆盖启用后的上传和归档。历史对象盘点须依据旧业务引用、备份和实际存储另行核对，不能按文件年龄盲删。已发货业务附件不自动删除，正式保留年限仍待业务确认。
