# PI收款方式与错误登记撤回

对照PRD 6.8，现有到账接口缺少结构化方式和受控撤回。下一批只处理错误登记更正，不执行退款或删除财务事实。

- 新到账保存BANK_TRANSFER/CASH/OTHER，OTHER说明必填。旧行保持NULL并显示未记录，不猜付款渠道。
- 撤回使用独立PI_PAYMENT_REVERSE权限、当前记录revision、requestId和必填原因；仅内部授权账号可执行，代理/PDA优先拒绝。原金额、凭证、到账与录入时间全部保留。
- 库存互斥锁→关联订单/占用→PI/系列→收款；与发货、收款、修订使用一致锁序。相同请求重试返回原结果，变化内容或过期版本拒绝。
- 撤回只减少有效收款合计，所有关联版本按实际累计重新显示。当前版本失去放行，重新核对门槛后需再次授权放行。已发生出库不撤销、不改变实物或已发数量；原库存保留不自动释放，必要时由授权订单关闭操作处理。
- 收款记录、当前放行状态和审计同事务，失败整体回滚。已发布PDF/Excel仍保留原字节。
- 页面明确显示撤回状态、原因、人员/时间；不能把操作描述为退款。按金额、方式、时间及说明进行到账请求幂等比较。

验收包含真实MySQL审计回滚、并发撤回一次生效、系列历史收款和发货门禁，以及普通财务与误授外部角色的真实HTTP拒绝路径。
