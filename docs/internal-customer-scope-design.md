# 内部客户授权范围与实施边界

PRD 2.3要求内部业务员仅访问授权客户/订单。V45及批次34已实现独立用户—客户关系、管理接口和页面，以及PI/订单/锁定/客户资料和相关文件的范围检查。businessOwner文字不是授权。本文记录实现边界；普通岗位浏览器与全项目最终两轮仍待验证。

## 授权模型

使用独立用户—客户关系和独立全客户范围权限。功能权限决定能否执行操作，客户范围决定能对谁执行；管理员仍可管理全部。代理商和PDA身份限制必须先于内部权限判断。授权修改需内部独立管理权限、请求版本、原因、审计及用户父行锁；默认不从负责人文字推断授权。

迁移不为既有销售/操作员自动授权全部客户。`CUSTOMER_ALL`角色仅含`CUSTOMER_SCOPE_ALL`，管理员必须明确分配给需要全范围的财务、仓库/PDA等岗位；其他内部Web账号通过用户—客户名单获得范围。没有名单的普通账号默认无客户业务数据，仍需另有功能权限。PDA不开放客户授权管理，出库工位仍需工位与操作权限，不能用全范围权限替代。代理的原代理归属校验仍优先生效。

`CUSTOMER_SCOPE_MANAGE`可单独授予内部Web人员，入口为“系统管理→客户授权”；可分页搜索内部账号和客户，读取现有授权并提交version/reason。该权限仅开放分配所需的账号和客户标识，不自动开放PI/订单内容。保存以目标用户父行排他锁、版本号、完整名单及审计同事务执行；业务写事务持有同一用户共享锁，撤权等待已授权写完成，之后的请求立即按新名单检查。管理接口清空名单不会覆盖独立的全范围角色。

## 必须统一覆盖的入口

| 数据 | 入口及旁路 |
| --- | --- |
| 客户 | 主资料列表、商务资料读写、PI/订单选择器、批量导出 |
| PI | 列表与总数、选项、详情、创建/编辑/取消/确认、修订历史/克隆、模板预览/固定文件/任务、商品图片/确认附件 |
| 收款和物流 | 收款登记/撤回/凭证、物流增改/历史/撤回/附件、实际出库批次详情 |
| 订单与锁 | 销售订单列表/详情/编号查询/增改/确认/取消、锁列表/编号/转单/释放、PI原子转换/锁选项、续占用/关闭剩余 |
| 通用查询 | modules/orders/customers/inventory-locks、DATA_EXPORT、业务看板、日志及搜索，不能通过总数或关键词匹配推断隐藏客户 |
| 车辆追溯 | 当前客户/历史出库/订单号与PI信息；仓库作业所需字段与商务信息应分别遵守角色和范围 |

列表必须在SQL分页和计数之前限定范围；详情和每个写入口必须后端校验，不能依赖前端选项。直接ID、同系列不同版本、附件对象ID以及第三方误授内部权限均须拒绝越权。后台到期和归档任务使用服务器保存的业务身份，不能因缺少请求线程而获得意外访问或停摆。

实现采用SQL范围子查询，在分页和count前过滤；追溯当前车辆按当前客户过滤，历史出库按该笔出库客户过滤，跨车辆复用部件的入库/返工查询也限制车辆范围。生产库存尚未归属客户的车辆与纯库存聚合仍遵守原生产/库存功能权限。全局自由文本日志可能混有其他客户资料，未获全范围的账号不开放通用日志/追溯事件预览，具体业务历史仍从相应受控入口读取。售后仍沿用独立的售后公司授权模型。

历史无customer_id的车型锁不能凭负责人文字猜测归属，普通逐客户账号不读取或转换；需显式全范围岗位核对。到期任务和归档工作器走各自服务器任务查询，不通过请求账号列表，也不会因无登录身份获得公开API访问。

## 验收要求

两销售各授权一个客户，另设全范围岗位；验证所有入口的可见记录和总数一致。撤权后重新请求立即拒绝；同客户不同代理不能突破代理限制。授权和业务写入并发须有明确的事务顺序。审计失败整体回滚。旧业务数据、已发布快照与库存在范围变更时保持不变。
