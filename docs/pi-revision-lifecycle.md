# PI修订生命周期与后续数量调整

## 当前实施规则（批次32，全量386项与16组真实HTTP通过）

- 一个系列最多一个修订草稿。相同请求重试返回同一版本，即使该版本已经发布或取消；不同请求不能建立并行草稿。
- 创建按库存互斥锁、原PI、系列行的顺序执行，版本分配、克隆、请求记录和审计同事务。取消的版本号保留，之后继续递增。
- 取消修订草稿只取消该草稿，不释放当前有效PI的库存占用，不修改当前版本或收款。取消有效版本须按系列检查全部历史收款和实际出库。
- 收款/出库后的商业资料通过修订草稿编辑；本阶段客户、代理商及币种保持系列一致，避免把旧到账或实际履约转到另一客户/币种。旧缺陷已产生的不同币种草稿在确认时仍会被拦截。
- 确认新修订不重复确认已履约子单；原CONFIRMED或RELEASED均须正确转为SUPERSEDED。新版本按系列到账重算付款状态，保持BLOCKED并重新授权放行。原归档及原收款所属版本不改变。
- 页面提供创建修订、失败后原请求重试、版本历史及跳转。版本历史仍需PI_READ，创建仍需内部PI_WRITE，历史财务金额按现有财务权限脱敏。

## 同SKU数量调整（批次33，全量391项与17组真实HTTP通过）

修订草稿允许修改原SKU数量，保存阶段不更改当前履约订单。确认持有库存互斥锁及全部订单/占用锁后重新校验实际已发量，按SKU计算一次总差额；同SKU的多个子单按稳定顺序分配减量，加量分配到最后一个有效未关闭子单。

先处理减量，再处理加量。加量同时检查SKU和车型库存，避免绕开历史车型承诺；到期或主动释放的占用不自动恢复。非零子单同步更新SKU占用明细、车型占用头和销售订单数量；减为零的未发子单保留原数量及链接，记录closed_qty并取消。调整后的状态按实际已发数量确定；已发流水从不改写。

来源锁定converted_qty代表原转换事实，保持原值；新差额通过PI_QUANTITY_REVISION审计保存修订ID、订单、SKU、前后数量及状态。新PI确认、旧版转历史、数量占用、付款状态及归档任务同事务；任一失败全回滚。已关闭子单不重开。旧车型订单无准确SKU占用时，允许保持原SKU数量的条款修订，调整数量须先处理准确履约关系。

## 新增和整行移除SKU（V48，批次38）

修订草稿可选择同客户、同代理的有效SKU来源锁定，保存`revisionSources: [{lockId, quantity}]`。每个来源只能选择一次，最多100笔，每笔数量1至100万。来源数量包含在PI对应SKU的总数量内，不是额外相加。新增SKU须有足额来源；已有SKU也可以选择新来源生成独立子单，余下数量仍按原子单调整规则处理。

V48保存所选来源的编号、SKU、数量、原截止和确认后的订单ID。保存或取消草稿不消耗来源，也不改变有效订单占用。确认时重新校验客户范围、内部PI_WRITE/ORDER_WRITE/AGENT_LOCK_WRITE、来源状态/剩余量/截止、启用SKU及车型；来源已续期须重新保存确认新截止，已到期或被其他转单消耗则拒绝发布。

确认在库存互斥事务中先释放减量，再处理加量与来源转换。每笔新增来源生成独立固定SKU子单，保存`SKU_REVISION`系列链接并沿用原截止，不重开关闭子单。内部转换使用随机请求号，确认本身以PI草稿状态、来源记录和同一事务保证只发布一次，防止普通转单预先占用可猜测请求号。

完全未发的SKU可以移除，旧子单保留数量和来源链接，记录关闭数量并释放剩余占用；已有实际出库的SKU不得从新修订消失。已关闭SKU以后重新加入须选择新来源。放行只校验仍有待发数量的占用，已移除的关闭子单不阻塞其他有效子单。新增订单、数量差额、来源转换计数、系列发布、旧版状态、审计和归档任务同事务；任何失败回滚全部变化。

Web编辑支持来源查询、选择、取消选择和移除商品；详情履约区展示本次修订来源及子单。代理视图不显示内部来源截止和选择记录。空来源字段不进入转换请求序列化，保留V47原请求幂等校验；非空来源不得用于首次创建PI。

## 尚未完成的边界

客户转移仍需完整的双客户授权、来源归属及历史付款/履约处理，不能直接替换PI快照。币种不允许把原到账金额换成另一币种。没有准确SKU的历史车型订单仍需核对和重建履约关系后才能调整数量。上述边界未因SKU新增功能而宣布完成；检查证据见实施台账。
