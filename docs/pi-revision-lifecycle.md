# PI修订生命周期与后续数量调整

## 当前实施规则（批次32，全量386项与16组真实HTTP通过）

- 一个系列最多一个修订草稿。相同请求重试返回同一版本，即使该版本已经发布或取消；不同请求不能建立并行草稿。
- 创建按库存互斥锁、原PI、系列行的顺序执行，版本分配、克隆、请求记录和审计同事务。取消的版本号保留，之后继续递增。
- 取消修订草稿只取消该草稿，不释放当前有效PI的库存占用，不修改当前版本或收款。取消有效版本须按系列检查全部历史收款和实际出库。
- 收款/出库后的商业资料通过修订草稿编辑；本阶段客户、代理商及币种保持系列一致，避免把旧到账或实际履约转到另一客户/币种。旧缺陷已产生的不同币种草稿在确认时仍会被拦截。
- 确认新修订不重复确认已履约子单；原CONFIRMED或RELEASED均须正确转为SUPERSEDED。新版本按系列到账重算付款状态，保持BLOCKED并重新授权放行。原归档及原收款所属版本不改变。
- 页面提供创建修订、失败后原请求重试、版本历史及跳转。版本历史仍需PI_READ，创建仍需内部PI_WRITE，历史财务金额按现有财务权限脱敏。

## 同SKU数量调整（批次33，全量391项与17组真实HTTP通过）

修订草稿允许修改原SKU数量，保存阶段不更改当前履约订单。确认持有库存互斥锁及全部订单/占用锁后重新校验实际已发量，按SKU计算一次总差额；同SKU的多个子单按稳定顺序分配减量，加量分配到最后一个有效未关闭子单。

先处理减量，再处理加量。加量同时检查SKU和车型库存，避免绕开历史车型承诺；到期或主动释放的占用不自动恢复。非零子单同步更新SKU占用明细、车型占用头和销售订单数量；减为零的未发子单保留原数量及链接，记录closed_qty并取消。调整后的状态按实际已发数量确定；已发流水从不改写。

来源锁定converted_qty代表原转换事实，保持原值；新差额通过PI_QUANTITY_REVISION审计保存修订ID、订单、SKU、前后数量及状态。新PI确认、旧版转历史、数量占用、付款状态及归档任务同事务；任一失败全回滚。已关闭子单不重开，新增SKU尚不支持。旧车型订单无准确SKU占用时，允许保持原SKU数量的条款修订，调整数量须先处理准确履约关系。

## 仍需完成的新增SKU及客户调整

以下是数量调整的检查清单及仍需扩展的边界，不代表新增SKU/客户转移已经实现：

1. 新数量不能低于实际累计已发数量；原出库流水、关闭数量、锁定转换历史不得改写。
2. 减量明确释放剩余占用；加量在同一库存互斥事务内校验SKU与车型两层可售量，避免抢占其他订单或遗留车型锁。
3. 多个子单同SKU应有稳定、可审计的差额分配，禁止对每个子单重复应用总量。
4. 已关闭或主动释放的子单不自动重开；已到期的占用不因修订自动恢复，须走已有授权续占用入口。
5. 数量、占用、系列发布、旧版状态、归档任务和审计任一失败全部回滚；并发出库与修订确认保持数量守恒。
6. 新增SKU或转移客户必须有完整的授权、库存及来源关联，不能仅修改PI快照绕开原履约客户校验。

第6项涉及新增SKU和客户转移仍待实现及验收；其他检查结果见批次33台账。
