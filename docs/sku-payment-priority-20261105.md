# SKU 预锁与付款优先占库调整

适用范围：SKU 库存锁定、锁定转订单 / PI、PI 收款和订单履约。历史 `MODEL_LEGACY` 车型承诺沿用原库存保障规则。

## 业务规则

- SKU 预锁允许超过当前合格库存，仍校验 SKU、客户、权限、数量、有效期和请求幂等。
- 累计有效收款大于零且达到 `depositRequiredAmount` 后，核对指定仓库、精确 SKU 和车型的可用库存。未付款 SKU 预锁不能阻挡本次占库。
- 当前库存不足以满足付款 PI 全部商品时，保存到账事实，不生成部分占用，也不取消其他订单；补货后可重试按仓占库。
- 占库成功后，按创建时间、ID 和类型核对相关未付款需求。剩余库存足够的保留，不足的整张 PI 及其关联子单取消；独立 SKU 订单整单取消，未转单的不足预锁释放。
- PI 任一 SKU 不足即整单处理，不按可供数量拆单。相关未发布修订一并取消，避免继续发布已取消订单的修订。
- 任何已有有效收款、已付款占用或已出库的订单不自动取消。部分收款未达到定金时不会触发优先占库。
- 原因保存到订单 / PI / 锁定备注及操作审计：`自动取消：其他客户已付款优先占库，剩余库存不足以满足整单`。审计另存触发付款的 PI ID。
- 出库仍要求达到 `shipmentRequiredAmount` 并通过原有放行、凭证和仓库校验。后来新增的超量预锁不会阻挡已付款订单履约。

## 实现与兼容

- `SkuLockService.create` 和 `LockOrderService.convert` 放开 SKU 预锁库存上限。
- `PiBusinessServiceImpl.reserveAfterPayment` 在整单占库后调用 `PaymentPriorityServiceImpl.cancelUnfulfillableUnpaidOrders`。
- `PaymentPriorityMapper.xml` 负责候选查询和状态更新；库存分配、整单取消及审计由 ServiceImpl 编排。
- 收款、占库、取消和审计在同一事务中执行，沿用 `ProductionGuard` 数据库互斥锁。异常向上抛出并回滚；重复收款请求沿用原幂等检查。
- 新增履约库存查询，与原页面需求量统计分开：页面仍展示预锁与订单需求及缺口，实际付款和出库只扣除已付款 SKU 占用及历史车型承诺。
- 没有修改 Controller API、DTO 字段或数据库结构；复用现有备注展示原因。部署本身不会批量处理历史订单，后续收款 / 占库成功时执行规则。
- 撤回错误收款不会自动恢复已经取消的其他客户订单，仍保留原业务记录及审计。

## 验证

独立本地 MySQL 8.4 验证了超库存预锁和转单、达到定金触发取消、部分收款保护、多 SKU 整单取消、付款本单缺货时保留到账、重复请求幂等、审计失败事务回滚、两笔并发定金竞争最后一台库存，以及新增超量预锁不阻挡付款订单。

验证结果：314 项常规测试通过；独立执行的 37 项 MySQL 场景通过（包括修正规则断言后重跑的 PI 转单场景）；`mvn -o verify` 和前端 TypeScript 校验、生产构建通过。常规 `verify` 中另有 201 项依赖环境的测试跳过，未宣称这些场景全部执行。详细日志位于 `tmp/payment-priority-build/`。
