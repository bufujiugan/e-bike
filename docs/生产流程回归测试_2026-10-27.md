# 生产流程回归测试（2026-10-27）

## 结论与修复状态

客户截图中的创建工单错误已定位并修复于本地源码：`ProductionManager.saveTask()` 在发送创建请求前直接执行 `crypto.randomUUID()`，当前客户 HTTP 入口的浏览器实际返回该方法为 `undefined`。不是 SKU、生产批次或计划数量导致的接口错误。

浏览器实测客户入口与本地普通 HTTP 验收域名均为 `isSecureContext=false`、`crypto.randomUUID=undefined`，而 `crypto.getRandomValues` 可用。新增 `createUuid()` 优先使用原生方法，不支持时通过安全随机字节生成标准 UUID v4。Web、PDA 的同类调用共 15 处已替换，覆盖工单、商品 Name、附件、SKU 锁定、锁定转订单、PI 修订/收款/物流和 PDA PI 出库。请求重试继续复用原标识。

**本次完成本地修复和独立环境验收，未发布到客户服务器，未提交或推送 Git。** 客户线上版本仍需发布修复后的 Web 和 PDA 构建产物才能生效。当前工作区已有其他页面改动；发布时应明确包含哪些改动。

## 真实工单 API 流程

| 环节 | 已验证行为 |
| --- | --- |
| 基础资料 | 创建车型、SKU、客户、仓库库位，登记并质量放行电机/电池/仪表 |
| 创建工单 | 一张工单计划两台车；同请求重试不重复创建；相同标识修改内容被拒绝；数量为 0 被拒绝 |
| 暂停恢复 | 暂停时拒绝首码，不产生单车记录；恢复后继续生产 |
| 失败首码 | 未登记部件被拒绝，单车与名额回滚，失败扫码独立记录 |
| 首码及恢复 | 自动创建单车；重复扫码不增加记录；可重新读取作业进度 |
| 工单隔离 | 当前工单不能继续扫描其他工单的单车 |
| 数量和取消 | 两个名额占满后拒绝新增；取消释放名额和部件，再用于其他单车 |
| 四码和完工 | 任意顺序扫描，两车分别生成总码；工单达到计划数量自动完成，并阻止继续生产 |
| 列表筛选 | 按 SKU、批次和已完成状态返回工单 |
| 标签打印 | 标签 HTML 包含真实车架码；重复完成不重复首打；领取、失败回报、补打成功 |
| 异常隔离 | 异常列表查询成功；隔离阻断入库；解除后允许入库 |
| 实物入库 | 两车入库后 SKU 实物库存为 2 |
| 锁定转单 | SKU 数量锁定、转销售订单、订单确认；重试不重复生成锁定或订单 |
| 分批出库 | 两车分两次出库，订单已发数量从 1 增至 2 |
| 生命周期追溯 | 车架、部件、整车总码均返回对应绑定和出入库历史 |

PDA 实操额外验证：首码后刷新恢复同一任务；普通 HTTP 上传真实 WebP 异常照片；在库换电池后绑定历史增至 4 条；旧电池自动隔离，复检后移出隔离清单；最终追溯同时出现生产、异常、入库、返工和出库记录。打印队列的领取、失败和补打用 API 验证；浏览器只验证真实标签渲染。
