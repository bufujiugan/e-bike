# 生产端验收与部署

> 以下为 2026-09-16 的历史实施与验收记录，地址和脚本环境不代表当前正在运行。全新安装请使用 [独立部署指南](deployment.md)；后续缺口以 [需求核查报告](生产端需求核查报告_2026-09-16.md) 为准。

当前交付阶段为生产端，PI、收款、物流、SKU 销售锁定及多商品订单接入等待生产验收后启动。

## 操作路径

1. Web「生产中心 → 商品 SKU」维护商品、规格、EAN-13、UPC-A、标签模板和产品图片；可下载 Excel 模板批量导入。车型及部件编码继续使用现有基础资料和导入入口。
2. PDA/H5「组装」选择 SKU、填写批次并建立生产任务。四码任意顺序扫描；已登记编码自动识别，尚未登记的新车架明确选择「车架」。不把未知部件猜作车架。
3. 同一任务号可刷新恢复或交给其他工位。各工位只允许扫描授权类型，综合组装工位允许全部类型。生产任务号是四码未齐时的共同标识。
4. 四码全部通过后自动绑定、生成聚合码并建立首次打印任务。重复扫码或重复完成不会再次绑定、生成总码或建立首打。
5. 配置 Windows 自动打印客户端后自动领取打印；也可在 H5 预览后人工打印。领取未回报超过五分钟标记「结果待核对」，不得自动重复出纸。
6. Web「异常隔离」或 H5 登记异常、上传照片。未解除异常阻止相关四码绑定、标签领取、入库及出库；管理员填写检查结果后解除。
7. 厂内换件沿用既有返工入口，保留总码及换件历史。所有拆下旧件先隔离，只有管理员「旧件复检」填写合格结果后才可复用。异常记录解除与旧件复检为独立步骤。
8. 换件或重生成总码时作废待打印的旧标签；正在打印时禁止换件/换码，先回报或等待超时核对。补打保留原商品/版式快照，使用车辆当前四码及当前总码，并记录原因。
9. 扫描聚合码入库；生产中心可按 SKU、仓库查看实物及隔离数量。通过总码、车架或历史部件码追溯整车和换件/出入库记录。

## 自动打印客户端

路径：`tools/print-client`。需要 Windows、Node.js 20+、已安装的打印机驱动及可访问服务的生产岗位账号。

```powershell
cd tools/print-client
npm ci
npx playwright install chromium
$env:BIKE_PRINT_URL = 'https://实际系统域名'
$env:BIKE_PRINT_TOKEN = '<登录接口返回的短期 accessToken>'
$env:BIKE_PRINT_PRINTER = '<Windows打印机名称>'
$env:BIKE_PRINT_TERMINAL = 'packing-01'
npm start
```

Token 只放运行环境，不写入源码。Token 到期/请求失败时客户端退出，重新登录后重启；已经领取但结果未知的任务必须核对，不会重新自动投递。此阶段为单工厂共享打印队列，多客户端互斥领取；工位与独立打印机路由不在当前配置范围。

只生成预览、不领取任务、不调用打印机：

```powershell
node client.mjs --preview '<打印任务号>'
```

浏览器已由企业统一安装时，可设置 `BIKE_PRINT_BROWSER` 为兼容 Chromium 可执行文件路径；未设置时使用 Playwright 安装的浏览器。虚拟打印验收可设置 `BIKE_PRINT_PRINTER=Microsoft Print to PDF` 和 `BIKE_PRINT_PDF_DIRECTORY`，执行 `node client.mjs --once` 处理一项任务并退出。

客户端按 203 DPI 渲染标签，检查内容是否超出纸高，提交给指定 Windows 驱动。`SUBMITTED` 仅表示提交系统队列，不保证真实出纸；现场必须验收纸张尺寸、硬边距、条码识读和断纸情况。两种初始标签为 100×150mm、100×100mm，可配置尺寸、标题及版式；长规格与长编码请先预览，超高时不会自动打印。

## 图片存储

默认本地文件模式，文件目录通过 `BIKE_PRODUCTION_FILE_ROOT` 指定，建议独立数据盘并配置备份。上传最大10MB，限 JPG/PNG，最大4000万像素；下载经过业务鉴权。

腾讯云 COS 模式设置：

| 环境变量 | 内容 |
| --- | --- |
| `BIKE_PRODUCTION_STORAGE` | `cos`；本地验收为 `local` |
| `BIKE_COS_REGION` | 存储桶所在地域，如 `ap-guangzhou` |
| `BIKE_COS_BUCKET` | 带 APPID 后缀的完整私有桶名 |
| `BIKE_COS_SECRET_ID` | 专用服务凭据 ID |
| `BIKE_COS_SECRET_KEY` | 专用服务凭据密钥 |

凭据从部署环境注入。桶保持私有，服务端鉴权后代理读取；图片数量和流量大时需结合监控调整带宽。切换模式不会自动搬迁旧文件，应保留原文件目录/COS 配置。数据库事务失败时清理本次上传对象，失败会记录附件编号告警；机器突然断电可能产生孤立文件，需要运维按数据库引用核对。

## 数据库与兼容

原 V1–V15 不修改；新 V16 Java Flyway 迁移由 Spring 注册，在开发/生产迁移目录均执行一次。结构 SQL 位于 `ProductionSchemaMapper.xml`，新增表和字段均含中文注释，迁移校验包含 XML 内容。发布后不得直接修改 V16 结构，后续变更新增版本。

业务新增 `/api/production/**`，已有组装、返工、仓库接口保持请求结构；共同增加占用、隔离及打印保护。`GET /api/trace/qr/{qrCode}` 为新追溯入口。新旧写入口使用同一事务互斥锁，优先保证单厂当前业务量的一致性。

回退时停用生产写入口并保留新增表；不能直接运行可绕过预占/隔离门禁的旧服务。标签打印不参与数据库事务，无法承诺设备层恰好出纸一次，未知结果始终人工核对。

```powershell
# 另一窗口，显式使用本机验收数据库。
cd F:\bike
$env:BIKE_ACCEPT_LOCAL='true'
python tools/production_acceptance.py start

# Web 与 H5 分别在各自目录运行 pnpm dev --host 127.0.0.1。
```

PDA现场访问需要局域网可达地址和HTTPS；不要把本机验收账号/空密码的本地数据库暴露到公网。生产服务器、存储容量与购买地址沿用《生产与PI订单系统建设方案》第五章。
