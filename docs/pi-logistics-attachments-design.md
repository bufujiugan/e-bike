# PI物流附件补全设计

PRD 6.9明确物流附件，现有确认附件与收款凭证不能替代物流用途。下一迁移V44为真实物流记录增加独立附件表，不改已应用迁移。

- 附件关联真实logisticsId，先校验PI读取范围及物流属于同一系列；原物流归属和修订不因上传改变。
- 内部PI_LOGISTICS_WRITE+PI_READ上传，客户只读CUSTOMER附件，INTERNAL附件不对外；可见范围只追加时确定。
- V47上传策略：内容验证后的JPG/PNG/WebP每图20MB，PDF/XLSX每文档50MB；每批1至20个、每物流记录累计50个。逐文件事务和请求标识支持部分成功及单个失败重试。
- requestId在物流记录内唯一，并发父记录锁，相同请求必须文件和可见范围完全一致。绑定失败清理对象，写入和审计同事务。
- 下载检查文件大小及SHA256，私有存储、权限控制与安全下载头；不提供任意对象键下载。
- 物流已撤回记录只读；计划/发运可追加。已有附件仍保留并能在历史物流查看，不复制到另一物流批次。
- 页面在每条物流记录提供附件入口和上传进度/失败原因；普通物流岗位和授权客户有真实HTTP检查。
