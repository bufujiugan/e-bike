# 统一履约配置与操作说明（2026-11-07）

> 复核状态：已补齐新单配置必填、多版式选择及后付款修订授权衔接，并在隔离本地环境完成四种组合的真实 HTTP 闭环。详细证据和交付边界见 `unified-fulfillment-requirements-audit-20261107.md`。尚未部署生产。

## 业务原则

国家不决定独立流程。复用 PI、仓库、SKU 库存、订单、实际出库批次、收款及附件，以发布的履约配置版本决定付款、交付、备货和单据要求。无配置的历史单据继续按原规则处理。

## 管理员首次配置

1. 在“PI 与履约 → 模板与银行资料”发布真实的卖方、联系方式及银行资料，记下模板编码和版本。版式可选“标准明细表”（STANDARD_V3）和“双栏发票”（INVOICE_V1），均可用于内销或外销；国家不决定版式。历史归档沿用其冻结版本。完整捷克样单尚未提供，当前不宣称已精确复刻该样单。
2. 打开“履约配置”，点击“发布新配置”，填写配置编码、版本和名称。配置名称按业务语义命名，例如“预付我方运输”“后付款客户提货”，不必按国家命名。
3. 选择已发布的 PI 模板及收款主体。选择适用仓库；留空表示所有启用仓库。卖方国家仍来自模板，出库仓库独立选择。
4. 选择付款方式：预付按本单金额门槛办理；后付款须逐单授权，并要求款项结清后结案。
5. 选择交付方式：我方安排运输，或客户货代到仓提货。客户提货不能同时要求“我方送货代仓”。我方运输按实际需要启用送货代仓环节。
6. 按业务选择销售合同、购销合同、出货表、备货确认、结清要求及 CI／RD／CMR。选择 RD 时同时要求发送与收回签署件。
7. 填写发布原因并发布。版本不可修改；调整规则使用“复制新版本”。停用限制新选用，已引用该版本的业务继续使用原规则。

## 业务员开单

1. 新建 PI，按现有规则关联已有订单，或明确选择无原订单的新业务。
2. 新单必须选择“履约配置”，缺少时前后端均拒绝。无配置的历史单据继续按原规则办理。系统带入贸易类型、收款主体、已发布模板；只配置一个适用仓库时自动带入仓库。多个仓库按实际选择，一张 PI 对应一个出库仓库。
3. “是否从国内出货”保留为出货属性；已选配置时，合同要求由配置控制，不由国家或内外销自动推断。
4. 后付款业务必须明确付款到期日；界面将库存和发货收款门槛带为 0，后端仍要求逐单授权，不能通过把金额填成 0 绕过授权。
5. 核对客户、SKU、数量、金额、付款和交付条款，保存并确认 PI。确认后的修订保持仓库、出货属性、主体、配置版本和付款期限不变；新的商业履约组合应另建 PI，避免覆盖已有出库及收款事实。

后付款 PI 修改商业明细后可先确认修订，再重新批准后付款与库存保留。累计到账保留；旧修订的后付款授权不继承，未重新授权不能放行。修订增加数量仍受可用库存约束；确认失败时订单数量、原修订状态和库存占用一并回滚。

## 付款、备货和出库

- 预付：登记实际到账，达到本单定金门槛后保留指定仓库库存，达到发货门槛后办理放行。
- 后付款：具备 `PI_RELEASE` 权限的人员在“批准后付款及库存保留”中核对客户、金额、付款期限，填写授权依据。普通 `PI_WRITE` 权限不能批准。授权时不允许付款期限已经过期。
- 后付款库存使用 `CREDIT` / `CREDIT_HELD`，真实收款仍独立登记。与 `PAID` 占用一起参与仓库、SKU、车型可用量计算；不能被付款优先清理当作普通未付款意向释放，也不能通过续期改回限时占用。
- 库存不足不会创建部分履约单；补货后重试按仓锁库。保留库存的执行入口和真实出库沿用库存互斥及事务校验。
- 配置要求出货表时，先上传文件，再记录实际发送日期及接收情况。按配置记录备货完成，并确认货代或提货安排。
- 我方运输填写实际承运商、单号及费用；客户货代提货填写提货仓库、联系人和实际安排。未知的客户运输信息如实说明，不虚构单号和运费。
- 授权放行不等于出库；仓管仍按现有 Web／H5／PDA 入口扫描实际车辆，并保留出库批次。客户货代提走不等于客户收到货。

## 单据、收款与结案

1. 在 PI 详情“业务单据附件”上传出货表、CI、RD、已签 RD 或 CMR。默认仅内部可见，需要给客户查看时明确选择可见范围。
2. 在对应流程节点选择当前 PI 修订的附件，填写实际发送或回收日期、接收方及办理情况。上传不会自动发送邮件或消息，也不会生成未经核对的正式单据。
3. CI、RD 发送依据已确认的送达事实；RD 回签依据已发送的 RD。CMR 可在出库后按实际取得情况登记，不必等待财务收款。
4. “其他待办”支持按实际进度处理文件和登记收款，后端仍校验必要前置条件。款项结清由真实累计到账与当前 PI 总金额比较，不能手工勾选。
5. 交付、配置要求的结清及文件全部满足后，填写结案说明。仅签收不表示业务结案。
6. 撤回出库或物流会使相关送达、单据及结案节点恢复待核对；原说明保留。撤回收款会重新计算结清及结案条件。

目前单据按 PI 修订及节点关联，运输仍关联实际出库批次；尚未增加“每个批次各自一套 CI／RD／CMR”的独立单据台账。单据不足时应先补齐当前 PI 的实际文件，不能把部分批次送达当作整单送达。

## 操作说明的新标签页

工作台右上角“生产到出库操作说明”中，逐步操作的所有业务入口使用原生链接，设置 `target="_blank"` 和 `rel="noopener noreferrer"`。点击后原说明保持打开、滚动位置保留；支持浏览器中键与复制链接。车型、标签模板、生产、库存、订单、PI 等链接直接指向相应业务页面。管理员配置入口可直接打开 PI 履约配置窗口。

业务流程图、角色时序图及逐步操作同步更新，移除了旧说明中的“无 PI 可直接出库”。已有库存可从库存和开单环节开始，无须重复生产。

## 实现与兼容

- 新增 `/api/pi-fulfillment-profiles` 查询、发布及启停接口；新增 `PiFulfillmentProfileService` / `PiFulfillmentProfileServiceImpl`，Controller 仅调用 Service，SQL 全部位于 Mapper.xml。
- PI 业务资料增加 `fulfillmentProfileId` 和 `paymentDueDate`；新单必须选择配置，后付款须填写到期日。历史无配置单据保留旧构造及请求标识兼容性。
- `layoutCode` 新增 `STANDARD_V3` / `INVOICE_V1`，不删除原枚举；前后端同步发布。旧快照继续按已保存 `documentRenderVersion` 导出，新版式归档有独立渲染标识。
- 订单引用不可覆盖的配置版本，修改或停用配置不重写历史单据。当前不支持在已确认单据的修订中改换配置和付款期限。
- `V57__unified_fulfillment` 是 Java Flyway 迁移，结构 SQL 位于 `PiFulfillmentSchemaMapper.xml`。新增配置表，扩展原库存占用 CHECK 约束以支持 `CREDIT`；不修改历史记录及已发布模板。
- Web 与后端须一起更新；新占用类型下，旧客户端可能不能完整显示状态。H5／PDA 继续调用现有出库接口，真实设备验收不在本次本地验证范围内。
- 回退时先停用新增配置，停止新增后付款业务。存在 `CREDIT` 占用时不能直接回退到不识别该状态的旧服务，也不能将其伪装为已收款；须保留兼容版本并核对未完成业务。配置、附件、到账及出库记录均保留。
