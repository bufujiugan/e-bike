# E-Bike 高保真交互原型

编制日期：2026-09-09。依据项目功能清单 V1.1 与新增售后需求设计。

## 打开方式

双击 `E-Bike_高保真交互原型.html`，用 Chrome 或 Edge 打开即可。样式、图标和交互已内置，无需安装依赖或连接业务服务器。

也可以在完整源文件目录内打开 `index.html`。修改样式或交互时编辑 `prototype.css`、`prototype.js`，单文件版本需重新打包。

## 评审路径

1. 公司后台：服务概览 → 售后案例 → 进入案例 → 工单信息 / 维修方案 / 发运信息 / 变更记录 / 旧件处理。
2. 审批：审核与审批 → 进入审核中的案例 → 审批案例；拒绝或退回必须填写原因。
3. 发运：配件发运 → 登记发货 → 核对联系人、地址、承运商、运单和日期。
4. 客户：右上角切换为“客户门户” → 申报售后案例 → 填入演示车辆 → 保存草稿或提交 → 进入案例留言。
5. 生产与库存：生产组装、整车档案、库存管理以及客户账号，用于评审新旧模块衔接。
6. 手机：缩小窗口至手机宽度，查看客户首页、申报表单及折叠菜单。

## 演示功能

- 案例查询、筛选、分页与 CSV 导出。
- 案例申报、必填检查、唯一编号及草稿恢复。
- 维修方案、审批、退回补充、状态更新与历史记录。
- 配件发运、客户沟通与旧件处理示意。
- 客户与内部角色视角切换。
- 所有演示变更仅保存在当前浏览器；在“原型导览”中可恢复初始演示数据。

## 业务边界

这是用于确认界面和交互的静态原型。数据、车辆插图、附件封面、故障判断和方案均为演示资料。角色切换不等于正式鉴权，不连接真实库存、邮件、物流或账号系统。附件只记录文件名，不保留文件正文。

基础看板、旧件处理的实施阶段待确认；知识库、趋势统计、车辆扫码自动带出为后期扩展预览。审批、保修、结案和库存联动应以双方确认后的规则实施。

## 浏览器验证

已检查案例搜索与重置、审批原因校验、审批与发运状态更新、客户视角隔离、草稿恢复、申报编号、案例留言、手机布局与菜单。检查后恢复初始 12 条演示案例。
