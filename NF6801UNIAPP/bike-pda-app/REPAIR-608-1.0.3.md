# BIKE PDA 1.0.3 / 103：先模拟验证再交付

## 结论与证据边界

本版修复1.0.2已经复现的控制回包/真实条码粘包丢码，并把串口接收到页面的关键路径变成可重复的本地模拟。模拟的是设备外部接口，不是把扫码成功结果硬编码后宣称通过。Android接口、Binder、电源、串口流和广播由测试替身提供；`Qs608Hardware`、`Qs608Receiver`、`Qs608ReceiveBuffer`、`Qs608Transport`与被替换的厂商读线程直接从待发布AAR加载。

仍没有USB设备。物理扫描灯、固件实际回包形式、Android运行时权限/设备服务、打印头与纸张出纸仍未真机验收。模拟覆盖已知协议和错误边界，不能证明所有固件行为。当前不要求客户反复安装中间包，不下线旧PDA网站。

## 已复现并修复

1. 1.0.2旧接收器在200ms内拼接`##55UP`和真实码，出口过滤导致两者一起丢失。改在原始字节层分离完整已知控制帧，再按CR/LF或200ms空闲边界提交条码；支持控制帧与UTF-8/GBK文本跨读取分片，不再以单次read作为报文边界。
2. 有明确行边界的连续条码独立发送；控制帧在条码前/后独立成行不吞码。无分隔符的控制帧嵌入码中无法无歧义判断，整行拒绝，不删除字符后拼成新码。没有任何分隔符且没有空闲间隔的多个条码也无法可靠分开，设备应保留行结束符。
3. 新分帧实现的首次回归暴露无换行条码尾部`z`/`#`被当作残缺控制前缀；已修复并保留反例测试。
4. 扫描请求延迟100ms期间可能开始打印；执行前重新检查硬件和打印状态，拒绝交错指令。
5. 串口接收中断时取消未完成码、停止待发队列并报告失败；不让打印在失去接收状态后继续静默发送，不重放部分数据。
6. 主动快速重扫同一码不再被上一请求的800ms广播去重窗口吞掉；同一次重复广播仍去重。页面关闭/重开时旧广播与旧等待不能回填新页面。

## 可重复运行

在本工程目录执行：

```powershell
./tools/test-hardware.ps1
./tools/build-hardware.ps1
./tools/test-hardware-integration.ps1
npm run check:release
npm run build:app
```

`test-hardware-integration.ps1`提取当前AAR后编译模拟外设，不重新编译业务兼容类。模拟生成的实际广播再回放到真实`common/device.js`和`common/page.js`，禁止使用业务写接口。普通`npm test`不具备Java模拟classpath时会显式跳过这一条跨语言回放；上述完整命令执行44项，无跳过。
