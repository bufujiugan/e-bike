# BIKE PDA 608 适配版

独立包名 `com.bike.pda608`，当前版本 `1.0.5-608`（105）。旧 APK 为 `com.bike.pda`、1.0.1（101），原工程和原签名未提供，因此新包与旧版并存；账号仍使用现有服务端账号，首次安装需重新登录。1.0.4修复账号信息加载失败时空菜单无内容的问题，提供15秒超时和重试入口；保留1.0.3对608控制回执 `##55UP` 的过滤修复。覆盖升级保留设置和会话。

## 安装与配置

安装包：`../output/apk/BIKE-PDA-608-1.0.5.apk`。支持 Android 6.0/API 23 及以上，包含 `armeabi-v7a` 和 `arm64-v8a` 两套官方库；WebView 建议 Chrome 64 及以上。已生成 Chrome 53 起的旧 JS 兼容包，但旧 WebView 及不同608固件必须实际验收。

1. 连接 USB，开启开发者选项与 USB 调试，在手持机确认此电脑授权。
2. 从项目根目录运行 `pwsh -File tools/install-pda.ps1 -Adb "你的adb.exe路径"`；也可复制 APK 到设备后手动安装。安装脚本不会卸载旧版。
3. 打开 **BIKE PDA 608**，填写服务根地址，例如 `https://服务器域名` 或局域网的 `http://服务器IP:端口`。不填 `/api`、`/pda` 或 `localhost`，优先使用 HTTPS。服务器应与原 PDA 使用同一套业务 API。
4. 按设备硬件选择扫码方式，默认 **硬解码**。软解码设备选 **系统广播接收**；系统已配置扫码结果键盘输出时选 **键盘输入**。不要同时启用广播与键盘输出，以免同一次扫描被输入两次。
5. 选择实际纸宽：58mm/384点，或80mm/570点。普通热敏纸不勾选黑标；间隙/黑标标签纸按耗材勾选。标签按纸宽等比缩放，条码可识读性及标签长度须现场确认。

主界面提供扫描、设备设置；Android 返回键也可打开设备设置或退出。设备设置展示型号、Android/WebView版本和设备服务状态。修改服务地址会清理本地登录状态。

608 固件如启用“设置 → 快霸（DuraSpeed）”，须打开列表内 **BIKE PDA 608** 的开关，允许该应用后台运行。实机发现快霸会在应用重开时阻止 WebView 渲染进程和设备服务启动，导致白屏；只放行本应用即可，不必关闭整个快霸。更新后如系统询问网络权限，应允许应用访问业务服务器。

## 已接入的能力

- 页面随 APK 打包，启动不依赖远程托管 H5；请求仍访问所配置服务器的 `/api`，无须修改后端 CORS。
- 实体 SCAN 键和屏幕扫描按钮；前台接收、短间隔去重；离开页面注销监听；请求处理中拒绝新扫码并提示重扫。
- 组装四码、入库校验、订单出库、PI整批出库、返工车辆/新件填码、追溯查询。入库和返工仍需操作员明确确认，批量出库仍按原流程确认。
- 生产异常照片的系统拍照/文件选择，支持多选图片。摄像头通过临时内容 URI 授权，不申请整盘存储权限。
- 服务端受控标签经 html2canvas 转为 PNG，使用608内置打印机送印。沿用原打印任务领取、人工结果回报和补打原因；未改服务端接口、权限或数据库。
- 打印前持久保存任务送印记录；同一任务在重启后也不能再次发送。缺纸、超时、退出中断均不自动重打。结果未知时停用本次硬件会话，须核对实物后重新进入应用。
- PI SKU 选择使用原生选择框，避免小屏滚动后弹出列表超出视口。修复原打印折叠区缺少状态绑定、无法展开的问题。

## 官方资料与协议

来源：`608资料/608硬解码扫描打印/QS608Demo_studio1.rar`。`app/libs/qs601sdk.jar`、两套 `libserial_port.so`、`ICommService.aidl` 直接取自该官方 Demo。厂商SDK的授权和使用条件沿用厂商约定。

| 项目 | 官方协议 |
| --- | --- |
| 串口 | SDK `MyApp.getSerialPort()`，`/dev/ttyS1`，230400波特率 |
| GPIO服务 | action `comm_com_service`，package `com.android.settings` |
| 实体扫描键 | `qsapi.intent.key_scan_down` |
| 硬解码触发 | GPIO 167；`1B 23 23 35 35 44 4E` |
| 软解码结果 | `com.android.server.scannerservice.broadcast`，extra `scannerdata` |
| 打印 | 24点列式ESC/P、一票一控、4096字节分包与GPIO忙闲流控 |
| 打印状态 | `7A F8`完成反馈、`14 00 0C 0F`缺纸反馈 |

58mm模式按官方Demo加入200点左侧补白；80mm不补白。实际居中与走纸需按设备固件/耗材测试。没有照搬Demo的无限忙循环、全局线程、`System.exit`及模糊过滤含 `MM`、`11` 的条码。

官方说明提示测试程序会争用串口：使用本应用硬解码/打印时，请先关闭厂商测试程序；若其后台仍持有串口，再由设备管理员按厂商指导停用。不要同时运行两个串口应用。

## 构建与维护

推荐使用项目提供的独立 Windows 构建脚本，需 JDK8、Node、pnpm、PowerShell。不用依赖旧版厂商工程的Gradle缓存。

```powershell
pwsh -File tools/prepare-pda-toolchain.ps1
pwsh -File tools/build-pda.ps1 -JdkDirectory "C:/Program Files/Java/jdk1.8.0_221"
```

工具链从 Google 下载 Android 30 平台与 Build Tools 30.0.3，校验官方公布散列。编译采用 javac、AIDL、D8、aapt、zipalign、apksigner。APK签名、对齐与SHA256在脚本中自动验证。`-SkipFrontend`仅用于已有 `build:pda` 产物的原生代码迭代。

`pda608-release.jks` 和 `signing.local` 是本机持久签名资料，已忽略入库。**务必安全备份这两个文件**；同包名后续升级必须沿用它们。不要发送给终端操作员，也不要与APK一起公开分发。

也提供 Android Studio/Gradle 工程（AGP7.4.2，Gradle7.5/JDK11），`preBuild` 自动构建并同步 H5；此路径默认Android开发签名，与上面本机交付签名不同，交付以构建脚本为准。

前端常规浏览器版本仍使用 `pnpm --dir bike-h5 build`，APK使用 `pnpm --dir bike-h5 build:pda`，两者共享业务代码。

## 验证与现场验收

自动检查及本轮结果见 `../docs/pda-608-adaptation.md`。浏览器检查采用模拟设备桥接和模拟API，不能代替真机验证。

现场需检查：安装/冷启动、登录与改密、实体键/屏幕扫描、连续扫码与失败重扫、切换页面、后台恢复、摄像拍照和图片上传、入库确认、PI和订单出库、返工确认、打印标签清晰度/纸宽/走纸、缺纸、打印中退出和补打。完成信号并不证明标签内容清晰或已贴到正确车辆，仍需人工核对并回报。

业务操作要求服务器在线，没有新增离线业务队列。键盘输入模式不占用串口，也不直接调用内置打印机。本轮未接入当前生产业务未使用的身份证、指纹或UHF模块。
